# Licence and notice files from upstream repositories

`scripts/third-party-notices.py` uses these files offline. `scripts/sync-third-party-licences.py` fetches all of them except those in `webview2-sdk/`, which are kept by hand (see below). After a change to `Cargo.lock` or `rust-toolchain.toml`, run `python3 -I scripts/sync-third-party-licences.py`, then `python3 -I scripts/third-party-notices.py`, and review the diff. The sync script needs the network; `scripts/check.sh` does not run it.

## Crates whose archives ship no licence file

`scripts/third-party-upstream.json` lists, for each repository, the files taken from it and the commit each crate was published from, as recorded in the crate archive's `.cargo_vcs_info.json`. Each project's files are in one folder here, at the path they have in its repository, so `LICENSE` in `burn/` is `LICENSE` at the root of the burn repository. The generator checks each commit against the archive, so a crate update fails until the sync script has fetched the files from the new commit.

The sync script fetches every listed file from the repository at the commit each of the project's crates was published from, and stops when the file differs between those commits. It records the current versions and commits, drops a crate that is no longer shipped or now ships its own licence file, and drops a project left with no crates, with its files. A shipped crate that newly ships no licence file gets a project of its own, with the licence and notice files found at its repository's root; the script prints what it added, for review in the pull request. When it cannot find them (no GitHub repository, no recorded commit, or no licence file at the root), it stops and says what to add by hand. It fetches everything and checks it before writing anything, so a failure leaves the files as they were.

objc2's `LICENSE.md` names each crate's licences without their texts, so the standard SPDX texts are shown after it (`standardTexts` in the manifest). The sync script keeps that field but does not add it to a new project.

A crate whose repository has no licence file at all goes in `withoutLicence` in the manifest, with the reason; it then shows the standard SPDX text. The sync script keeps the reason when the crate's version changes.

The generator checks the manifest before using it: each project lists at least one licence file, every listed file is a plain relative path to a file in the repository that is not blank, each project's files share one folder of their own here, and every `withoutLicence` entry gives its reason. A crate's own notice files are shown beside those taken from its repository, and files from one repository are named by their path below the folder holding them, so no file replaces another with the same name. Settings labels each file with where it came from: the repository at that commit, or a standard SPDX text. `tests/third_party_notices_test.py` covers these checks and `tests/sync_third_party_licences_test.py` covers the sync script.

## Other components

- `rust`: `COPYRIGHT`, `LICENSE-APACHE` and `LICENSE-MIT` from https://github.com/rust-lang/rust at the tag of the toolchain in `rust-toolchain.toml`. The standard library is linked into every build. The sync script fetches them at that tag and sets the version in `scripts/third-party-extra.json`; the generator fails until they match.
- `webview2-sdk`: `LICENSE.txt` and `NOTICE.txt` from the Microsoft.Web.WebView2 1.0.3800.47 NuGet package, https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.3800.47. On Windows (MSVC), `webview2-com-sys` 0.39.1 links `WebView2LoaderStatic.lib` from that SDK version into the app. Its entry in `scripts/third-party-extra.json` names that crate version in `shippedWith`, so the generator fails when the crate changes. The crate's archive does not record which SDK version it carries, so the sync script leaves these files alone: when the crate changes, read the SDK version from its repository at the new release and update these files and the entry by hand.
